# git-commit

1. リポジトリの指示とコミット規約を読み、`git status --short`、`git diff`、`git diff --cached` でステージ済み・未ステージの変更を確認する。未追跡ファイルも対象に含まれるか確認する。
2. 依頼範囲の差分を読み、認証情報・秘密鍵・個人データの混入が疑われる場合は内容をチャットへ出さずにコミットを止める。プロジェクトの検証コマンドで必要な確認を行い、成功済みの検証は変更や新たな懸念がなければ繰り返さない。失敗・未実施は報告し、修正が必要なら依頼範囲で対応する。
3. `git add -- <path>...` で対象を指定してステージする。他の作業の差分や、ユーザーがステージした無関係の変更が混在している場合は、一括コミットや勝手なunstageを避け、対象を確定する。
4. `git diff --cached --check` とステージ済み差分を確認し、論理的にまとまる単位で `git commit` を実行する。規約がなければ `feat: ...`、`fix: ...`、`docs: ...` などのConventional Commits形式にする。複数行のメッセージはファイルに書き、`git commit -F <message-file>` で渡す。
5. `git log -1 --oneline` と `git status --short` で結果を確認し、コミットID、変更の要点、検証結果、残った変更を報告する。

通常のコミット依頼ではamend、履歴の書き換え、pushを行わない。フックを無効化せず、失敗時は原因を確認する。
